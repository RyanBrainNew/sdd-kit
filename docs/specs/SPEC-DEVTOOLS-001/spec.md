## 2. 范围声明

- In-Scope：
  1. 新增一套可独立部署到 GitHub Pages 的静态介绍站，包含首屏、价值主张、工作流、架构、命令示例、适用场景、FAQ 和页脚。
  2. 新增自动发布该站点的 GitHub Actions 工作流，发布内容仅包含站点目录，不包含 Spec 与运行时工件。
  3. 重写仓库根 `README.md` 为开源项目首页结构：徽章、一句话定位、Why、特性、Quickstart、工作流图、CLI 参考、文档导航、目录结构、贡献方式和许可证状态。
  4. 将原 README 中的长篇执行说明迁入 `docs/` 下的完整指南，并在新 README 中提供入口，保证原有知识不丢失。
  5. 更新仓库 About 文案素材：Description、Topics 与 Homepage 地址建议，并在具备权限时写入 GitHub 仓库 homepage 字段。
- Out-of-Scope：
  1. 不修改 `sdd/scripts/sdd.py`、`sdd/core.py`、`sdd/cli.py` 的状态机、Gate 或 CLI 行为。
  2. 不修改 MCP 工具集合、`sdd/manifest.json` 和 `sdd/VERSION`。
  3. 不将 `docs/specs/`、`.sdd/`、Gate 报告或业务仓库数据发布到公开站点。
  4. 不购买域名、不配置自定义域名、不接入访问统计或第三方评论。
  5. 不决定仓库可见性，不新增或替换开源许可证文本。
  6. 不提供完整英文站点；站点与 README 以中文为主，保留英文项目名、命令和术语。

## 3. 业务上下文

### 3.1 干系人与角色

| 角色 | 诉求 | 使用场景 | 责任边界 |
|---|---|---|---|
| 平台团队 | 让外部读者在 1 分钟内理解 sdd-kit 解决什么问题 | 分享仓库链接、对外介绍 | 维护核心与发布流程 |
| 业务仓库开发者 | 确认接入成本与日常命令 | 首次接入前评估、clone 后查阅 | 只改业务配置与 Spec |
| Agent/IDE 使用者 | 找到唯一的 Agent 协议入口 | 配置 Agent、排查流程 | 不修改核心状态机 |
| 开源访客 | 判断项目是否值得试用或贡献 | 从 GitHub About 进入官网 | 提 Issue、PR、讨论 |

### 3.2 业务流程

1. 访客在 GitHub 仓库 About 区点击 Homepage 链接进入官网。
2. 访客在首屏看到定位、三条硬约束和“30 秒理解”的流程摘要。
3. 访客通过页面内的 Quickstart 复制接入命令，或跳转到 README 与完整指南。
4. 访客从文档导航进入架构、接入、Agent 协议和 FAQ。
5. 平台团队合并改动后，Pages 工作流自动重新发布站点。

### 3.3 业务规则

- BR-001：官网只展示可公开的产品说明，不展示 Spec、Gate 报告、内部项目名和业务仓库信息。
- BR-002：README 的第一屏必须同时出现项目名、一句话定位、版本徽章、CI 徽章和官网入口。
- BR-003：站点与 README 的命令必须与当前 CLI 一致，不能出现未实现的命令。
- BR-004：人工检查点只有 Spec 确认与 PR 合并两个，对外表述不得增加或减少。
- BR-005：许可证状态必须如实呈现；仓库未声明许可证时，不得展示开源许可证徽章或声称已开源。

## 4. 功能需求与验收条件

### FR-001 官网首页

- 功能描述：提供单页静态介绍站，覆盖首屏、核心问题、工作流、架构、命令、适用场景、FAQ 与页脚。
- 用户场景：访客从 GitHub About 或分享链接进入，快速判断项目价值并找到接入文档。
- 验收条件：
  - AC-001-1：Given 站点已发布，When 访客打开首页，Then 首屏可见项目名、一句话定位、版本号、主 CTA 和次 CTA。【执行路径：浏览器人工评审 + 本地静态检查】
  - AC-001-2：Given 访客位于首页，When 依次滚动到各区块，Then 可见“三条硬约束”“一次需求的完整链路”“人类检查点”“CLI 命令”“适用与不适用场景”“FAQ”六个内容区。【执行路径：浏览器人工评审】
  - AC-001-3：Given 访客使用 360px 宽视口，When 打开首页，Then 页面无横向滚动，导航折叠为可展开菜单，正文与代码块保持可读。【执行路径：浏览器响应式人工评审】

### FR-002 视觉与交互

- 功能描述：站点采用深色科技风视觉，提供轻量动效、复制命令、锚点导航和移动端菜单，且不依赖构建步骤。
- 用户场景：访客在桌面或手机浏览，获得与主流开源项目官网一致的完成度。
- 验收条件：
  - AC-002-1：Given 访客点击任一命令块的复制按钮，When 剪贴板写入成功，Then 按钮文案变为“已复制”并在 2 秒内恢复。【执行路径：浏览器人工评审 + 本地脚本检查】
  - AC-002-2：Given 访客关闭 JavaScript，When 打开首页，Then 所有正文、导航链接和代码内容仍可阅读，仅复制与滚动动效降级。【执行路径：浏览器禁用脚本人工评审】
  - AC-002-3：Given 访客使用键盘 Tab 导航，When 焦点移动到导航、按钮和链接，Then 焦点样式清晰可见，锚点可跳转到对应区块。【执行路径：键盘人工评审 + 可访问性静态检查】
  - AC-002-4：Given 操作系统开启“减少动态效果”，When 访客打开首页，Then 入场动画与滚动动效被关闭。【执行路径：浏览器媒体模拟人工评审】

### FR-003 专业化 README

- 功能描述：将根 README 重写为开源项目首页，保留深度内容入口。
- 用户场景：访客在 GitHub 仓库页 30 秒内理解定位、安装方式、工作流和文档位置。
- 验收条件：
  - AC-003-1：Given 访客打开仓库首页，When 阅读 README 前 40 行，Then 可见项目名、定位、CI/版本/Python/文档徽章、官网与完整指南链接。【执行路径：人工评审】
  - AC-003-2：Given 访客想立即试用，When 查找 Quickstart，Then 可在同一屏内找到接入命令、恢复命令和最小验证命令。【执行路径：人工评审 + 命令逐条执行】
  - AC-003-3：Given 访客需要深入细节，When 查看文档导航，Then 可跳转到完整指南、架构、Agent 协议、接入步骤、MCP 部署和 FAQ。【执行路径：链接检查】
  - AC-003-4：Given 仓库未声明许可证，When 访客查看 README 末尾，Then 看到明确的许可证状态说明，且页面不存在 MIT/Apache 等许可证徽章。【执行路径：人工评审】

### FR-004 深度内容归档

- 功能描述：把原 README 的长篇章节迁移到独立指南，保留全部关键事实与命令。
- 用户场景：已接入团队继续查阅原 Q&A、状态机、MCP 与多微服务说明。
- 验收条件：
  - AC-004-1：Given 新 README 已发布，When 访客点击“完整指南”，Then 打开包含原 README 全部一级章节的指南文件。【执行路径：章节对照检查】
  - AC-004-2：Given 访客使用旧 README 中的任一 CLI 命令，When 在指南中检索该命令，Then 能找到对应说明，命令文本未改变。【执行路径：命令清单抽样比对】
  - AC-004-3：Given 新 README 与指南同时存在，When 检查相对链接，Then 所有站内链接均指向存在的文件或锚点。【执行路径：本地链接检查脚本】

### FR-005 自动发布与仓库门面

- 功能描述：通过 GitHub Actions 将站点目录发布到 Pages，并提供 About 区配置素材。
- 用户场景：平台团队合并后无需手工上传；访客通过 About 的 Homepage 进入官网。
- 验收条件：
  - AC-005-1：Given 工作流文件已合并到默认分支，When 触发 Pages 发布，Then 工作流只上传站点目录并成功生成部署产物。【执行路径：GitHub Actions 运行记录 + 本地 YAML 检查】
  - AC-005-2：Given 站点已发布，When 访问默认 Pages 地址，Then 首页返回 200 且资源全部为相对路径，可在子路径下加载。【执行路径：部署后 HTTP 检查】
  - AC-005-3：Given 仓库管理员打开 About 设置，When 参照交付说明填写 Description、Topics 和 Homepage，Then 三项内容与站点和 README 的定位一致。【执行路径：人工评审】
  - AC-005-4：Given `gh` 具备仓库管理权限，When 执行 homepage 写入，Then 仓库 `homepageUrl` 等于默认 Pages 地址。【执行路径：GitHub API 查询】

## 5. 边界与异常

| 场景类型 | 场景描述 | 关联FR/AC | 预期行为（错误码/降级策略/提示信息） |
|---|---|---|---|
| 边界场景 | 仓库保持私有且账号无 GitHub Pro/Team | FR-005；AC-005-1 | 工作流保留，Pages 启用失败时在交付说明中提示“私有仓库需公开或升级计划”，站点文件仍可在本地打开 |
| 边界场景 | 访客禁用 JavaScript | FR-002；AC-002-2 | 正文、导航和代码完整可读，复制按钮隐藏或保持静态 |
| 边界场景 | 访客使用 360px 窄屏 | FR-001；AC-001-3 | 单列布局，无横向滚动，代码块内部横向滚动 |
| 边界场景 | 仓库未来新增许可证 | FR-003；AC-003-4 | README 许可证段落改为指向 LICENSE 文件，并可补充对应徽章 |
| 异常场景 | 复制 API 不可用 | FR-002；AC-002-1 | 按钮显示“复制失败”，不抛出未捕获异常，命令文本仍可手工选中 |
| 异常场景 | Pages 部署失败 | FR-005；AC-005-1 | Actions 日志可见失败步骤，站点目录不被删除，修复后可重跑 |
| 异常场景 | 站内链接指向不存在的文件 | FR-004；AC-004-3 | 本地链接检查失败并列出路径，合并前必须修复 |

## 8. 数据模型

- 核心实体定义：不涉及持久化数据；站点内容为静态 HTML/CSS/JS，README 与指南为 Markdown。
- 数据流说明：Markdown 与静态站点文件随 Git 提交 → Actions 构建 Pages 产物 → 浏览器读取静态资源。

## 9. 约束与假设

- 技术约束：只使用原生 HTML、CSS、JavaScript；不引入 Node 构建链；Pages 工作流使用官方 `actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages`。
- 技术约束：Python 侧只使用标准库，站点实现不得新增 Python 运行时依赖。
- 业务约束：不改变 SDD 状态机、Gate、CLI 与 MCP 的行为和文案契约。
- 业务约束：对外表述必须与 `sdd/agent-contract.md` 一致，人工检查点只有两个。
- 假设条件：默认分支为 `main`；站点使用仓库级 GitHub Pages 默认地址。
- 假设条件：仓库可见性与许可证由人决定；未决定前 README 如实标注“未声明许可证”。
